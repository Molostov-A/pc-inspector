# Журнал решений (ADR, кратко)

Формат: дата — решение. Контекст. Последствия.

## 2026-11-07 — Стек: Python + SQLite + FastAPI + ванильный JS/ECharts + MCP
Контекст: пользователь пишет на Python; приложение должно легко развиваться разными LLM.
Решение: один процесс на Python, индекс в SQLite, веб-UI без сборки (никакого npm), MCP через официальный SDK.
Последствия: нет шага сборки фронтенда; UI проще, чем на React, но любой агент правит его без инфраструктуры.

## 2026-11-07 — Плагинные анализаторы с единым форматом Report/Finding
Контекст: анализов будет много, и добавлять их должны разные агенты.
Решение: `@register` + метаданные `params`; CLI, API, MCP и UI строятся из реестра автоматически.
Последствия: новый анализатор — один файл; нестандартный UI нужен только для специальных экранов.

## 2026-11-07 — ИИ только анализирует и предлагает, выполняет человек
Контекст: ошибка ИИ при удалении файлов необратима и опасна.
Решение: в MCP нет инструментов, меняющих ФС; выполнение — только через UI/CLI с подтверждением; нет безвозвратного удаления.

## 2026-11-07 — Схема v2 и атомарная замена скана (F1.6–F1.10, N3)

Версия 2 добавляет атрибуты файлов, статистику тома и системных файлов, а также `settings.exclude_paths`.
Относительные исключения отсчитываются от текущего корня. История сканов добавляется на этапе 7.
Новый корень и пересоздание индексов фиксируются одной транзакцией WAL. До её завершения
читатели видят прежние данные. `synchronous=OFF` выставляется перед транзакцией скана,
а исходное значение возвращается после фиксации или отката.

## 2026-11-07 — Замер на временных деревьях (F1.12)

На каждом томе создано новое дерево из 100 000 файлов по 128 байт и 1 001 папки.
Время включает обход и создание индексов SQLite. Пик памяти измерен как рабочий набор процесса Windows.
На B: скан занял 0,460 с при пике 41,5 МиБ. На C: скан занял 0,492 с при пике 41,6 МиБ.
Ошибок доступа в обоих прогонах не было. Файлы создавались непосредственно перед сканом.
Замеры целевых путей и лимита памяти на 5 млн файлов остаются открытыми.

## 2026-11-07 — Автономный веб-интерфейс (F5, F6, N7)

В пакет включён [Apache ECharts 6.1.0](https://github.com/apache/echarts/tree/6.1.0/dist)
с файлами LICENSE и NOTICE. SHA-256 файла `echarts.min.js` —
`b66b25aeb4df84e33199dc21694014d336d222cbd9deb0e5a7c14bd6aa0d0fd0`.
OpenAPI доступна в JSON. Swagger UI и ReDoc отключены, чтобы не загружать внешние ресурсы.
До первого скана отчёты читают пустой SQLite-индекс в памяти.

## 2026-11-08 — MCP SDK 2.x (F7)

В установленном официальном SDK 2.x `FastMCP` переименован в `MCPServer`.
Используем `mcp>=2,<3` и транспорт stdio. Совместимость проверяется в обычном и legacy-режимах SDK.
SQL выполняется через `mode=ro` и `query_only`. Авторизатор SQLite дополнительно ограничивает
разрешённые операции чтением. [Руководство по миграции SDK](https://py.sdk.modelcontextprotocol.io/migration/)

## 2026-11-08 — Обратимые действия и журнал намерений (F3.1–F3.7)

Перемещение ограничено одним томом и выполняется через Windows rename без перезаписи.
Перед переносом в карантин записываются намерение в SQLite и manifest.json. При прерывании
начатый пункт не повторяется автоматически. История позволяет проверить и откатить перенос.
Для Корзины используется современный backend Send2Trash. Очистка карантина переносит элементы
в Корзину. Итог показывает объём обработанных данных отдельно от освобождённого места.

## 2026-11-08 — Защита Корзины и очистка содержимого (F3.1, F3.3, §9.1)

Перед отправкой в Корзину проверяются квота тома, NukeOnDelete, политики и длина путей.
Если настройки прочитать нельзя, отправка запрещается и предлагается карантин.
Даты папок исключены из отпечатка: NTFS отдаёт их из листинга родителя с задержкой.
Черновики, созданные раньше, при выполнении будут пропущены и их нужно собрать заново.
Действие `clear_contents` оставляет папку и переносит в карантин только объекты старше суток
и старше плана. Занятые файлы пропускаются, поэтому отпечаток всей папки для него не сверяется.

## 2026-11-08 — Кэш поиска дубликатов (F2.1)

Частичные и полные BLAKE2b-хэши сохраняются пакетами. Повторное чтение содержимого
пропускается при совпадении размера, времени изменения и создания и идентификатора файла.
Файлы с несколькими жёсткими ссылками исключаются целиком, чтобы объём не завышался.
В одной группе отчёт показывает до 200 путей и считает потенциальный объём по всем копиям.

## 2026-11-08 — Инвентаризация программ Windows (F2.2, F2.3)

Сбор использует классические записи Uninstall. Отдельный опциональный сбор Appx отложен.
Prefetch по имени EXE применяется, когда имя сопоставляется с одним индексированным путём.
UserAssist сопоставляется по полному пути. При неполном чтении реестра прежние записи
сохраняются, а отчёт об остатках ждёт полного сбора.
Запуск использует актуальный UninstallString и передаёт Windows отдельно EXE и аргументы.
Поддерживаемый MSI-код продукта открывается через системный msiexec с ключом /x.
[Свойства реестра Uninstall](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key)
[Ключи Windows Installer](https://learn.microsoft.com/en-us/windows/win32/msi/command-line-options)

## 2026-11-08 — История сканов и раскладка файлов (F1.11, F2.4, F2.6)

Снимки привязаны к пути корня без учёта регистра и фиксируются вместе с индексом.
При обновлении старого индекса первый перескан сохраняет предыдущие данные для сравнения.
При пересечении порога снимка в 50 МиБ изменение приблизительное, что указано в отчёте.
Папки назначения создаются после подтверждения плана. Откат возвращает файлы по исходным путям.
